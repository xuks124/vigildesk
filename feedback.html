Feedback ｜ 意见与反馈

Found a bug? Missing a feature? Tell us — feedback goes straight into the public feedback pool, is triaged every 3 days and summarised into a weekly plan. If you leave a contact method, you get a reply when your item is handled. ｜ 遇到 Bug？想要新功能？告诉我们——反馈直接进入公共反馈池， 每 3 天分类分拣、每 7 天汇总排期；留下联系方式，处理后会收到回执。

How it works ｜ 流程：
  1. Submit this form — it opens a pre-filled, structured issue in our public feedback pool (GitHub Issues). ｜ 提交本表单——会打开一个已 预填好的结构化 issue 到公共反馈池（GitHub Issues）。
  2. Every 3 days feedback is auto-classified (bug / feature / help / praise / billing / other). ｜ 每 3 天自动分类（缺陷/建议/求助/好评/账单/其他）。
  3. Every 7 days a digest plans what gets fixed or added next. ｜ 每 7 天周报排期下一轮修复与新增。
  4. Items with a contact method get a receipt when handled. ｜ 留有联系方式的条目在处理后收到回执。

You need a GitHub account to submit (the pool lives on GitHub Issues). You may write in English or Chinese. ｜ 提交需要一个 GitHub 账号（反馈池托管在 GitHub Issues）。中英文均可。

New feedback ｜ 新反馈

Submitting opens github.com/xuks124/vigildesk/issues/new with your text pre-filled — nothing is sent anywhere until you press "Submit new issue" there. ｜ 提交按钮只是带着你的内容打开 GitHub 新建 issue 页面；在你点击 GitHub 上的 “Submit new issue” 之前，不会发送任何数据。

Security issue? ｜ 发现的是安全漏洞？

Do not post exploit details in a public issue. There is no public security inbox yet — reply to your Paddle order confirmation email with “[Security]” in the subject, or use the contact method on this page's form but choose “Other” and write “security” in the title; keep details minimal until we reply. ｜ 请勿在公开 issue 中发布可利用细节。 私密上报通道正式上线前：请回复你的 Paddle 订单确认邮件并在主题注明 “[Security]”；或在本页表单选择“其他”并在标题注明 security，细节在收到回复前尽量精简。
